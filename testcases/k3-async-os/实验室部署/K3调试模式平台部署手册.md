# K3 JTAG 调试模式：平台部署文档

本文档说明在 K3 板子部署为 JTAG 调试板的流程。部署完成后，板子每次上电自动走 JTAG 引导流程，停在 U-Boot 命令行，OpenOCD 就绪，同学可远程 GDB attach。

## 1. 固件清单

以下文件由我们提供，平台存档并校验哈希。对不上就别用。

| 文件 | 用途 | 哈希 |

| k3-jtag-ram-opensbi-uboot.itb | OpenSBI + U-Boot，不含 RCPU | md5 `685d6f9f115c82844104d3d788d071e8` |

## 2. 硬件装配

### 2.1 调试扩展卡和 J-Link

1. TF 槽插入 SpacemiT 官方调试扩展卡。扩展卡把 MMC1 引脚切换为 JTAG 信号。
2. 扩展卡上的 JTAG 接口接 J-Link 排线。
3. J-Link 的 USB 接主机。

注意：扩展卡占用 TF 槽，板子不能同时用 TF 卡。

### 2.2 FORCE_RECOVERY 跳线帽

12 Pin 排针的 10 号针（FORCE_RECOVERY）和相邻地针之间盖跳线帽，永久短接。

效果：每次完全断电再上电，BootROM 读到 strap 拉低，直接进 USB 下载模式。不需要中途断开，不需要继电器。

### 2.3 三根线接主机

| 线 | 板端 | 主机端 | 用途 |
|---|---|---|---|
| USB-TTL 串口线 | 12 Pin 排针串口引脚 | USB 口 | 日志、U-Boot 命令 |
| USB 下载线 | USB-C 数据口 | USB 口 | fastboot 刷固件 |
| J-Link USB | 调试扩展卡 JTAG 口 | USB 口 | JTAG 调试 |

### 2.4 电源

- 规格：12 V / 5 A。
- 12 V / 1.5 A 适配器会让 PMIC 闭锁（灯灭、风扇不转），必须用 5 A。
- 电源通断由主机控制：继电器、可控 PDU 或可控集线器任选。
- 引导脚本需要独立的上电、断电、重启命令，不和串口会话绑定。

### 2.5 下载模式外观

下载模式下风扇不转、灯灭是正常的。下载模式切断了 3.3 V 供电链。

## 3. 主机环境

### 3.1 操作系统

Linux，Ubuntu 22.04 以上实测可行。

### 3.2 必装软件

| 软件 | 版本要求 | 安装方式 |
|---|---|---|
| fastboot | 34.0.4（android-tools） | `apt install android-tools-adb` 或源码编译 |
| OpenOCD | 0.12.0 | 源码编译（需启用 jlink 和 riscv 支持） |
| uhubctl | 最新 | `apt install uhubctl` 或源码编译 |

OpenOCD 编译参考：

```bash
git clone --branch v0.12.0 https://github.com/openocd-org/openocd.git
cd openocd
./bootstrap
./configure --enable-jlink --enable-riscv
make -j$(nproc)
sudo make install
```

### 3.3 udev 规则

多板共用主机时，用 udev 规则按 USB 路径或序列号固定设备名。示例：

```udev
# /etc/udev/rules.d/99-k3-debug.rules

# J-Link（按序列号）
SUBSYSTEM=="usb", ATTR{idVendor}=="1366", ATTR{serial}=="<J-Link序列号>", SYMLINK+="k3-jlink-01"

# 串口（按 USB 物理路径）
SUBSYSTEM=="tty", ATTRS{idVendor}=="1a86", ATTRS{idProduct}=="7523", KERNELS=="1-2.1", SYMLINK+="k3-serial-01"
```

装完规则后 `sudo udevadm control --reload && sudo udevadm trigger`。

单块板试点时可以不配 udev，直接用 `/dev/ttyUSB0` 等默认名。

### 3.4 USB 自动恢复准备

确认 J-Link 所在 USB 端口支持 per-port power switching：

```bash
sudo uhubctl
```

输出里找 J-Link 所在的 hub 和 port。如果显示 `(power switching: yes)` 或类似标记，uhubctl 可以控制该端口断电重上。如果不支持，需要在 J-Link 和主机之间串一个支持 per-port power switching 的 USB Hub。


## 4. OpenOCD 配置部署

我们提供两个配置文件：

| 文件 | 用途 |
|---|---|
| interface/jlink.cfg | J-Link 适配器配置 |
| target/spacemit-k3.cfg | K3 RISC-V target 配置 |

存放到主机固定目录，如 `/srv/k3-debug/openocd/`。

关键参数（已写入配置文件，此处列出供核对）：

| 参数 | 值 | 说明 |
|---|---|---|
| adapter speed | 100 kHz | 更快在当前固件下不稳定 |
| CLUSTERS | {0} | 只开 cluster0 |
| CLUSTER0_COREIDS | {0} | 只开 core0，SMP=1 |

OpenOCD 启动命令：

```bash
openocd -f /srv/k3-debug/openocd/interface/jlink.cfg \
        -f /srv/k3-debug/openocd/target/spacemit-k3.cfg
```

生命周期规则（全部实测，必须遵守）：

- 只能在 debug FSBL 跑过之后起。起早了 JTAG 扫描全 1，OpenOCD 进入不可恢复状态。
- 一个 J-Link 只允许一个 OpenOCD 实例。起之前确认无残留进程。
- 停止用 `kill -9`。OpenOCD 不响应 SIGTERM。
- 扫描失败或 J-Link 掉线后，kill -9 再重启。

## 5. 引导脚本部署

### 5.1 脚本位置

我们提供 `k3-jtag-boot.sh`，放到主机 `/srv/k3-debug/` 下。

### 5.2 配置项

脚本头部有以下变量，平台按实际硬件填写：

| 变量 | 含义 | 示例 |
|---|---|---|
| SERIAL_DEV | 串口设备路径 | /dev/ttyUSB0 |
| SERIAL_BAUD | 波特率 | 115200 |
| POWER_ON_CMD | 上电命令 | 平台自定义 |
| POWER_OFF_CMD | 断电命令 | 平台自定义 |
| FASTBOOT | fastboot 路径 | /usr/bin/fastboot |
| FIRMWARE_DIR | 固件目录 | /srv/k3-debug/firmware |
| OPENOCD_BIN | OpenOCD 路径 | /usr/local/bin/openocd |
| OPENOCD_CFG_DIR | OpenOCD 配置目录 | /srv/k3-debug/openocd |
| USB_RECOVERY_CMD | USB 恢复命令（可选） | uhubctl -a cycle -l 1-2 -p 3 |
| MAX_RETRY | 引导失败最大重试次数 | 3 |
| STEP_TIMEOUT | 每步超时（秒） | 30 |

### 5.3 脚本行为

脚本执行第一层引导的 9 步状态机：

1. 断电 → 上电（FORCE_RECOVERY 已永久短接，上电即进下载模式）
2. 等 BootROM fastboot 设备出现
3. fastboot stage FSBL.bin → fastboot continue
4. 等串口出现 U-Boot SPL 2022.10，等 SPL fastboot 设备枚举
5. fastboot stage ITB → fastboot continue
6. 等串口出现 U-Boot 2022.10，等 Full U-Boot fastboot 设备枚举
7. fastboot continue，等串口出现 => 提示符
8. 起 OpenOCD，确认 JTAG 扫描成功
9. 输出就绪信号

任一步超时：自动断电，从头重试，最多 MAX_RETRY 次。全部失败则报错退出。

### 5.4 与平台服务的集成

脚本是参考实现。平台可以：

- 直接调用脚本，解析 stdout 的就绪信号和退出码。
- 改造为服务内部逻辑，保留时序和规则不变。

集成要点：

- 引导期间串口由脚本独占。就绪后平台把串口转交同学终端。
- 脚本的串口日志输出到 stdout 和日志文件，平台保留副本。
- 重新引导 = 再调一次脚本。脚本自己断电重来。
- 脚本不管第二层（TFTP、booti）。就绪后同学自助。

## 6. 验证清单

部署完成后逐项验证：

- [ ] 固件哈希全部匹配
- [ ] 跳线帽盖好，上电后风扇不转、灯灭（下载模式正常外观）
- [ ] `fastboot devices` 能看到 BootROM 设备（version-brom: 1.0）
- [ ] 运行引导脚本，串口依次出现 SPL → U-Boot → `=>` 提示符
- [ ] OpenOCD 日志出现 `Examined RISC-V core; found 4 harts`
- [ ] 从另一台机器 `gdb-multiarch -ex 'target remote <主机IP>:3333'` 连接成功
- [ ] `monitor halt` 停住 CPU，`monitor resume` 放行
- [ ] 串口里 `tftpboot` 加载内核并 `booti`，内核正常跑
- [ ] booti 后 J-Link 掉线时，USB 恢复命令生效，OpenOCD 重启后 GDB 可重连
- [ ] kill -9 OpenOCD → 断电，收尾顺序正确

## 7. 已知边界

部署时不需要处理，但需要对齐的信息：

- DDR 容量上限 4 GB（旧版 debug FSBL 限制）。
- SMP=1，JTAG 100 kHz。更快或多核在当前固件下不稳定。
- ITB 不含 RCPU 固件。含 RCPU 会让 booti 后 JTAG 失效。
- TFTP 初始化约半数概率报 `EQOS_DMA_MODE_SWR stuck -110`，同学重试即可。

将来固件升级只换文件和参数，脚本逻辑不重写。
