# 环境配置

本文档说明本项目的两个调试工具的安装、运行与调试配置方法：

- **osgdb**：跨特权级 OS 调试器（VS Code 扩展，调试类型 `osdb`）
- **async-debug**：跨特权级 Rust 异步跟踪调试器（VS Code 扩展，调试类型 `ardb`）

StarryOS 与 Async-os 的调试配置作为使用示例附在文末，完整的验证过程见决赛文档「测试与验证」章节。

## 测试环境

| 环境指标 | 环境参数                            |
| -------- | ----------------------------------- |
| 操作系统 | Ubuntu 24.04 LTS（x86_64）          |
| VS Code  | 1.80 及以上                         |
| Node.js  | 20 及以上                           |
| GDB      | gdb-multiarch 15.x（或架构对应的 gdb，如 riscv64-unknown-elf-gdb） |
| QEMU     | qemu-system-riscv64（8.2 及以上）   |
| Rust     | nightly-2026-05-26（被调试目标需要） |

两个工具通过 GDB remote 协议连接 QEMU 中的调试目标，GDB 与 QEMU 只需可用即可，无版本强绑定（GDB 需支持 Python 扩展，async-debug 依赖 GDB Python 脚本）。

## osgdb：安装与运行

```bash
git clone https://github.com/OSDebugger/osgdb.git
cd osgdb/code-debug
npm install
npm run compile
```

运行方式（二选一）：

1. **开发模式**：在 VS Code 中打开 `osgdb/code-debug` 目录，按 F5 启动扩展开发宿主（Extension Development Host），在新窗口打开被调试的 OS 项目
2. **安装模式**：打包为 `.vsix` 后安装（需要 `@vscode/vsce`：`npm install -g @vscode/vsce`，然后 `vsce package`），在 VS Code 扩展面板中「从 VSIX 安装」

验证编译无误（可选）：`node out/test/testOSStateMachine.js`，37 个状态机单元测试全部通过即环境就绪。

## async-debug：安装与运行

```bash
git clone https://github.com/OSDebugger/async-debug.git
cd async-debug
npm install
npm run compile
```

运行方式与 osgdb 相同（F5 开发宿主或 `vsce package` 打包安装）。此外可用仓库自带测试用例快速验证异步跟踪功能：

```bash
# 启动调试会话（launch 模式，不涉及 OS）
make debug TESTCASE=minimal
```

## 调试配置说明

两个工具都以 `launch.json` 配置文件为入口，`request: "attach"` 模式下调试器负责启动 QEMU、连接 GDB remote 端口并自动加载符号。通用配置项如下：

| 配置项 | 含义 |
| ------ | ---- |
| `type` | 调试器类型：`osdb`（osgdb）或 `ardb`（async-debug） |
| `request` | 统一为 `attach`：调试器连接已在 QEMU 中运行的目标 |
| `cwd` | 被调试项目的工作目录 |
| `gdbpath` | GDB 可执行文件路径 |
| `qemuPath` / `qemuArgs` | QEMU 路径与启动参数（最后需含 `-s -S` 开启 GDB 端口并暂停启动） |
| `target` | GDB remote 端口（如 `:1234`） |
| `executable` | 内核 ELF 路径，调试器用它加载内核符号 |
| `stopAtConnect` | 连接后暂停在启动点，等待用户操作 |
| `program_counter_id` | 程序计数器（PC）寄存器编号（RISC-V 为 32） |
| `kernel_memory_ranges` / `user_memory_ranges` | 内核/用户地址空间范围（`[start, end)` 十六进制字符串对），用于判断 PC 所属特权级 |
| `first_breakpoint_group` / `second_breakpoint_group` | 初始断点组与默认目标断点组 |

跨特权级调试的专用配置项：

| 配置项 | 含义 |
| ------ | ---- |
| `border_breakpoints` | 边界断点：标记内核↔用户切换位置。支持三种指定方式：`{ "filepath": ..., "line": ... }`（文件+行号）、`{ "marker": "..." }`（扫描源码注释）、`{ "function": "..." }`（函数名）。可加 `"direction": "kernel_to_user" / "user_to_kernel"` 标注流向 |
| `hook_breakpoints` | Hook 断点：命中时执行 `behavior` 中的 JS 函数（`functionBody`），返回值作为下一断点组名称，执行后自动继续、对用户透明 |
| `filePathToBreakpointGroupNames` | 可编程函数：把源码文件路径映射到断点组名列表 |
| `breakpointGroupNameToDebugFilePaths` | 可编程函数：把断点组名映射到符号文件路径（返回纯路径，或 `{ path, textAddr }` 指定加载地址） |

async-debug 特有配置项：

| 配置项 | 含义 |
| ------ | ---- |
| `osDebug` / `asyncDebug` | 启用跨特权级调试 / 异步跟踪（两者同时启用即为异步 OS 调试） |
| 白名单与 Trace | 无需配置项，通过 Async Inspector 面板操作：Gen Whitelist 生成候选函数列表 → 勾选 crate → Apply Whitelist → 对目标函数 Trace 设置追踪根 |

**配置函数（`functionBody`）是字符串形式的 JS 代码，其中可使用 `require`、`fs` 等 Node 模块拼接路径；三处组名必须一致**：`filePathToBreakpointGroupNames` 的返回值、Hook 行为函数的返回值、`breakpointGroupNameToDebugFilePaths` 接收的组名，任一处不一致会导致切换到空组或断点挂错组。

## 使用示例一：StarryOS（osgdb）

编译要求：内核 release 编译并保留调试符号（RUSTFLAGS 附加 `-g`）；用户程序带 `-g` 编译后挂载进磁盘镜像。

```json
{
    "version": "0.2.0",
    "configurations": [{
        "type": "osdb",
        "request": "attach",
        "name": "StarryOS Debug (riscv64)",
        "cwd": "${workspaceFolder}",
        "target": ":1234",
        "gdbpath": "/opt/riscv/bin/riscv64-unknown-elf-gdb",
        "executable": "${workspaceFolder}/target/riscv64gc-unknown-none-elf/release/starryos",
        "qemuPath": "qemu-system-riscv64",
        "qemuArgs": [
            "-L", "/usr/share/qemu", "-m", "1G", "-smp", "1",
            "-machine", "virt", "-bios", "default",
            "-kernel", "${workspaceFolder}/StarryOS_riscv64-qemu-virt.bin",
            "-nographic",
            "-device", "virtio-blk-pci,drive=disk0",
            "-drive", "id=disk0,if=none,format=raw,file=${workspaceFolder}/make/disk.img",
            "-device", "virtio-net-pci,netdev=net0",
            "-netdev", "user,id=net0,hostfwd=tcp::5555-:5555,hostfwd=udp::5555-:5555",
            "-s", "-S"
        ],
        "first_breakpoint_group": "kernel",
        "stopAtConnect": true,
        "program_counter_id": 32,
        "kernel_memory_ranges": [["0xffffffc000000000", "0xffffffffffffffff"]],
        "user_memory_ranges": [["0x0000000000001000", "0x0000004000000000"]],
        "border_breakpoints": [
            { "function": "enter_user", "direction": "kernel_to_user" },
            { "function": "starry_kernel::syscall::handle_syscall", "direction": "user_to_kernel" }
        ],
        "hook_breakpoints": [{
            "breakpoint": { "file": "${workspaceFolder}/kernel/src/syscall/task/execve.rs", "line": 65 },
            "behavior": {
                "functionArguments": "",
                "functionBody": "const p = await this.getStringVariable('path'); const name = p.replace('./','').split('/').pop(); return '/home/iristseng/data/StarryOS/user_apps/' + name + '.c';",
                "isAsync": true
            }
        }],
        "filePathToBreakpointGroupNames": {
            "isAsync": false,
            "functionArguments": "filePathStr",
            "functionBody": "if (filePathStr.includes('kernel/src')) { return ['kernel']; } else { return [filePathStr]; }"
        },
        "breakpointGroupNameToDebugFilePaths": {
            "isAsync": false,
            "functionArguments": "groupName",
            "functionBody": "if (groupName === 'kernel') { return ['${workspaceFolder}/target/riscv64gc-unknown-none-elf/release/starryos']; } else { return [groupName.replace('.c', '')]; }"
        }
    }]
}
```

使用：F5 启动调试 → 状态机在 `enter_user` 处自动切入用户态断点组 → shell 中执行 `/test_user` 等命令 → Hook 断点自动识别程序并创建进程组。完整验证流程见决赛文档 §4.3。

## 使用示例二：Async-os（async-debug）

编译要求（详见 async-debug 仓库的 `async-os-original复现文档.md`）：内核 release + `-g -C strip=none`（裸汇编短跳转限制，不能 debug 编译；release 默认剥除调试信息）；用户程序 `+crt-static` 静态化并 `opt-level=0`（动态链接 PIE 符号基址错位；O3 吞掉行表）；Hook 目标函数加 `#[inline(never)]`（LTO 内联消除符号）；`user_boot` 的 TESTCASES 设为 `"pipetest"`。

```json
{
    "version": "0.2.0",
    "configurations": [{
        "type": "ardb",
        "request": "attach",
        "name": "async-os pipetest debug",
        "cwd": "${workspaceFolder}",
        "target": ":1234",
        "gdbpath": "gdb-multiarch",
        "executable": "${workspaceFolder}/apps/user_boot/user_boot_riscv64-qemu-virt.elf",
        "qemuPath": "qemu-system-riscv64",
        "qemuArgs": [
            "-m", "2G", "-smp", "1",
            "-machine", "virt", "-bios", "default",
            "-kernel", "${workspaceFolder}/apps/user_boot/user_boot_riscv64-qemu-virt.bin",
            "-device", "virtio-blk-pci,drive=disk0",
            "-drive", "id=disk0,if=none,format=raw,file=${workspaceFolder}/disk.img",
            "-device", "virtio-net-pci,netdev=net0",
            "-netdev", "user,id=net0",
            "-nographic", "-s", "-S"
        ],
        "first_breakpoint_group": "kernel",
        "second_breakpoint_group": "pipetest",
        "stopAtConnect": true,
        "program_counter_id": 32,
        "kernel_memory_ranges": [["0xffffffc000000000", "0xffffffffffffffff"]],
        "user_memory_ranges": [["0x0000000000000000", "0x0000004000000000"]],
        "border_breakpoints": [
            { "function": "<taskctx::arch::riscv::TrapFrame>::user_return", "direction": "kernel_to_user" },
            { "function": "trampoline::task_api::user_task_top::{async_fn#0}", "direction": "user_to_kernel" }
        ],
        "hook_breakpoints": [{
            "breakpoint": { "function": "trampoline::executor_api::init_user" },
            "behavior": {
                "functionArguments": "args",
                "functionBody": "try { await this.miDebugger.captureConsoleOutput('set language c'); const out = await this.miDebugger.captureConsoleOutput('x/s *((unsigned long long*)(args.buf.inner.ptr.pointer.pointer)+1)'); const m = /0x[0-9a-f]+:\\s*\"(.*)\"/.exec(out); return m ? m[1] : 'user'; } catch(e) { return 'user'; }",
                "isAsync": true
            }
        }],
        "filePathToBreakpointGroupNames": {
            "functionArguments": "filepath",
            "functionBody": "const m = /user_apps\\/([^\\/]+)\\//.exec(filepath); if (m) return [m[1]]; return ['kernel'];",
            "isAsync": false
        },
        "breakpointGroupNameToDebugFilePaths": {
            "functionArguments": "groupName",
            "functionBody": "if (groupName === 'kernel') return []; const fs = require('fs'); const path = require('path'); const dir = 'user_apps/target/riscv64gc-unknown-linux-musl/release/'; if (fs.existsSync(dir)) { const files = fs.readdirSync(dir).filter(f => f === groupName && !fs.statSync(path.join(dir, f)).isDirectory()); if (files.length > 0) return [path.join(dir, files[0])]; } return [path.join(dir, groupName)];",
            "isAsync": false
        }
    }]
}
```

使用：F5 启动调试 → Async Inspector 面板中 Gen Whitelist → 勾选用户 crate → Apply Whitelist → 以 `trampoline::task_api::user_task_top::{async_fn#0}` 为追踪根 Trace → 继续执行，断点组自动切换、白名单自动重建；在 `user_apps/pipetest/src/implementation/async_await.rs` 的 18、19、29、35 行设断点，命中后 Async Inspector 展示贯穿内核态与用户态的调用树。完整验证过程见决赛文档 §4.4。
