# K3 开发记录 04:插调试卡后风扇不转——根因与对策

- **日期**:2026-11-10
- **状态**:✅ **根因确认**(卡上连 12Pin 第 10 脚的 FORCE_RECOVERY 线,上电即强制进 USB 下载模式,非板卡故障);**解法:拔掉该线即恢复插卡正常启动,无需任何改线或软件手段**

## 现象(实测确认)

| 状态 | 上电后风扇表现 | 串口表现 |
| --- | --- | --- |
| 不插调试卡 | 立即转(全速),系统起来后由软件控速 | BootROM → U-Boot SPL → U-Boot → Bianbu 正常启动 |
| 插调试卡,**第 10 脚线已接** | **转一下(不足 1 秒)就停**;拔卡不复原,必须完全断电重开 | BootROM 直接进 USB 下载模式(Recovery),停住等主机 |
| 插调试卡,**第 10 脚线不接** | **正常转**,与不插卡无异 | 与无卡基线逐字节一致:try sd → bm:3 报错 → bm:4 NOR → 正常启动 Bianbu |

其他已排除变量:与 J-Link 是否连接无关;与 OS 是否启动无关。**唯一决定变量 = 卡上连到 12Pin 第 10 脚(FORCE_RECOVERY)的那根线**(2026-11-10 受控实验确认)。

> ⚠️ 注意"转一下再停"这个细节:说明 5V/3.3V 使能链**短暂拉起过、随后被撤掉**——不是电源硬件损坏,是电源链被下载模式状态"关掉"了。

## 根因:扩展卡改变了启动 strap,BootROM 进入 USB 下载模式

### 串口实测证据(决定性)

插卡冷启动捕获(`~/data/k3-serial-card.log`,2026-11-10):

```
sys: 0x10001200        ← 无卡基线是 0x10000200,bit12 被改变 = 启动 strap 变了
bm:2                   ← 无卡基线是 bm:3(SD)→bm:4(NOR)
usb_init : enter
ROM: usb download handler   ← 永远停在这,等主机推固件
```

无卡基线(`~/data/k3-serial.log`,2026-11-04):

```
sys: 0x10000200
try sd...
bm:3
ERROR:   CMD8
ERROR:   sd f! l:90
bm:4
nor m:0xc8 d:0x6017      ← 落到 QSPI NOR,正常启动链
```

### 机制

1. BootROM 上电瞬间把某些引脚电平锁存为 **strap**(官方资料:Boot SEL=Strap1/Strap0 选启动介质,Download SEL=Strap2,`0`=USB 下载 / `1`=UART 下载)
2. 官方调试卡上有一根飞线接 12Pin 第 10 脚 **FORCE_RECOVERY**(power-on strap)。卡在 TF 槽内且线接上时,上电瞬间 FORCE_RECOVERY 被拉低,BootROM 不走存储启动链,直接进 **USB 下载模式(bm:2,`ROM: usb download handler`)**——`sys` 寄存器 bit12 从 `0x10000200` 变 `0x10001200`(bit12 = FORCE_RECOVERY 锁存)。这正是前人博客记录的官方流程入口:完全断电 → FORCE_RECOVERY → 上电
3. 线不接时,调试卡在 TF 槽里**无害**:BootROM 照常 `try sd...` 对卡做 SD 枚举、`ERROR: CMD8` 报错(卡不是存储卡)、`bm:4` 落 NOR,启动链与无卡基线逐字节一致(2026-11-10 受控实验,`k3-serial-exp2.log`)
4. 风扇为什么停:载板原理图 sheet24/25,U2503(WS4603E)是风扇电源开关——`VDD_5V_SYS`(常电)→ U2503 IN → OUT=`VDD_5V_FAN` → J13 风扇座;U2503 的 **EN=`BUCK_3V3_EN`**(模组 PMIC 输出)。Recovery 模式下模组撤掉 `BUCK_3V3_EN` → 风扇断电。风扇的 PWM/TACH 悬空时是全速,但**电源被切了**,所以停;启动链推起来(FSBL 之后)电源链恢复、风扇转回

### 两种模式都是官方设计的入口,按需切换

- **第 10 脚线接上**:上电自动进 Recovery——前人 golden flow 的入口(断电 → FORCE_RECOVERY → 上电 → fastboot 推 Debug FSBL → SPL → OpenSBI → U-Boot → 内核)。适合 JTAG 早期引导调试
- **第 10 脚线不接**:正常启动链,插卡状态可直接走 k3flash.sh(adb + U-Boot + load scsi + booti)跑 async-os。适合当前启动链阶段的日常调试
- 之前"TF 触点改变 strap、需要屏蔽卡触点"的推测**不成立**,无需任何 hack
- 载板原理图(官方 26 页,k3-com260_kit_v02)上没有任何 strap 拨码开关,也没有 TF 槽元件——strap 和 TF 槽都在模组侧,不存在"拨开关改模式"这条路(入门文档中"strap 在载板上有拨码开关"是官方 EVB 的通用描述,不适用于 COM260)

## 对策(按优先级;OS 没跑时软件无从谈起)

### 方案 0(最省事,推荐优先):拔掉第 10 脚线

如果不依赖 Recovery golden flow,直接把卡上连到 12Pin 第 10 脚的线拔下(12Pin 端松开即可):插卡状态正常启动、风扇自然转,**零硬件修改、随时可插回**。JTAG 调试接入前,日常跑内核用这个状态即可。

### 方案 A:风扇外接常电(推荐给不想动板子的人,零风险、完全可逆)

1. 风扇插头从 J13(4 针 1.25mm 白色小座)拔下
2. 废旧 USB 线剪断:红=5V、黑=GND,与风扇红/黑线对绞包好(PWM/TACH 悬空 = 全速)
3. USB-A 头插手机充电头常供

- 优点:不动板子、无烙铁
- 缺点:多一路外接电源,风扇与板子电源状态无关(充电头一直接着,风扇就常转)

### 方案 B:旁路 U2503(一体化:上电即转,正常启动时照旧由系统控速)

- U2503 的 **IN(pin5)与 OUT(pin1)短接**(一坨锡桥);或细飞线从 U2503 pin5(IN,`VDD_5V_SYS`)到 C2501 的 `VDD_5V_FAN` 端(C2501 是 0402 电容,焊盘比 SOT-23-5 好下手)
- 效果:J13 恢复常电。不插卡正常启动 → Linux thermal/PWM 照常控速;插卡(下载模式)→ PWM 悬空 = 全速
- 可逆:吸锡即恢复

### ⚠️ 取电坑(2026-11-10 更正早期文档的错误建议)

常电 5V 只有 **`VDD_5V_SYS`** 一路(DC 圆口一上电就有,来自 SY8370TMC 降压)。以下 5V **在下载模式下不可靠,不要用**:

| 取电点 | 为什么不可靠 |
| --- | --- |
| 40Pin 排针的 5V | 经 Q2401 PMOS 开关(BD_DISABLE/EN_PWR_PATH,BMCU 控制),下载模式大概率无电 |
| 板载 USB-A 口 VBUS | 经 USB hub 的电源开关,下载模式无电 |

可靠的 `VDD_5V_SYS` 取电点:U2503 的 IN 侧(pin5)、其输入电容 C2500、U9006 降压输出。

## 附 2:插卡状态跑 async-os-original 实测(2026-11-10)✅

**状态:调试卡在 TF 槽、第 10 脚线不接,全程风扇正常,内核跑通并正常 shutdown。**

- 流程(纯串口,不需要 adb):上电正常启动 Bianbu → s 风暴打断 U-Boot autoboot → `=>` 提示符 → 三条命令:

```
load scsi 0:2 0x140000000 asyncos.bin   # 929920 bytes read
load scsi 0:2 0x138000000 k3.dtb        # 142063 bytes read
booti 0x140000000 - 0x138000000         # LOGO → coroutine_test 全输出 → Shutting down
```

- 完整日志:`~/data/k3-serial-exp2.log`
- 操作教训 1:**s 风暴在提示符出现后要立刻停**。若风暴多跑几分钟,几百个 's' 会堵在 U-Boot 输入队列里,后续命令要等板子消化完才执行(实测延迟 ~40 秒,k3flash.sh 的 60s 超时可能误判)
- 操作教训 2:本机 adb 服务在插上 CH340 后卡死(`adb devices`/`start-server` 均挂起),纯串口流程可完全绕开 adb;修 adb 前,k3flash 用 `-u` 直接模式或手工三条命令
