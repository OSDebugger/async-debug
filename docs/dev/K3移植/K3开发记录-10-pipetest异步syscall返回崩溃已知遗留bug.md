# K3 开发记录 10:pipetest 崩在异步系统调用返回路径 —— async-os 已知遗留 bug(暂不修)

- **日期**:2026-11-10
- **面向读者**:完全没学过硬件也能看懂(概念先行,现象在后,词表在最后)

## 这篇记录解决什么问题

hello_world 在 K3 上通过之后,pipetest(异步管道测试)跑着跑着把**整个内核**搞崩了。这篇记录讲清:崩在哪一步、为什么不是 K3 移植的错、以及为什么决定**暂时不修**。

## 先讲三个概念(大白话版)

### 1. 同步系统调用 vs 异步系统调用 = 打电话 vs 点外卖

用户程序找内核办事(读文件、读写管道),叫**系统调用**。

- **同步** = 打电话问:程序停下,等内核当场把结果告诉它。
- **异步** = 点外卖:程序下单后**不等**,继续干别的;它给内核留一个"收货地址",内核办完把结果**写回这个地址**,再敲门叫醒它。

### 2. 收货地址装在哪 = 寄存器 t1 这个"口袋"

下单(ecall 指令)时,程序要把三样东西塞进三个固定的"口袋"(CPU 寄存器):

| 口袋 | 装的东西 |
|------|----------|
| t0 | 旗子:"我是异步单" |
| **t1** | **收货地址**(结果写回哪里) |
| t2 | 门牌号(办完敲门叫醒谁) |

### 3. 页错误 = 送货送到不存在的地址(前几篇的老朋友)

内核往"收货地址"写结果时,如果那个地址**根本不存在**,CPU 立刻报警。前几篇见过这个报警(LoadPageFault),这次是**写**的时候踩空(StorePageFault)。

## 现象(崩溃时发生了什么)

串口日志显示 pipetest 跑到一半:

```
READ(3)     → 内核还没准备好数据,回了个"稍等"(EAGAIN)
CLOSE(3)    → 读者这边放弃等待,关掉管道
(6.8 毫秒后)
Unsupported kernel trap StorePageFault ...
    stval: 0x1        ← 往"地址 1"写结果,踩空了
```

用大白话讲:pipetest 的读者想读空管道,内核回了"稍等";读者放弃,关掉管道;这个动作惊动了内核里那张**还没完成的"外卖单"**——内核的服务员(ktask)不管订单有没有被取消,照样按单子上写的地址送货,而单子上的地址是 **1**(一个根本不存在的地址)→ 送货踩空 → 内核 panic,整台机器停机。

## 排查过程(怎么证明不是 K3 移植的错)

1. **查用户程序有没有写错地址**:把烧进板子的 pipetest 二进制反汇编(逐条看机器指令),下单前它确实把"收货地址"塞进了 t1 口袋 —— **用户程序没错**。
2. **查内核"收口袋"的环节**:trap 入口的汇编代码(用户程序进内核时,内核把口袋里的东西抄到一张"寄存单"trap frame 上)先抄 t1 再干别的,顺序正确 —— **抄写环节没错**。
3. **查"寄存单"的格式**:内核 Rust 代码读这张单子的结构与汇编抄写的槽位一一对应(repr(C) 布局) —— **读单子的环节也没错**。
4. **但内核读到的 t1 = 1**,不是收货地址。所以问题锁定在**内核异步系统调用路径上对寄存器的处理** —— 与用户说的"和寄存器有关"完全吻合。
5. **用户确认**:这是 async-os 的**遗留 bug**(在 qemu 上正常跑也跑不过),之前在另一台电脑上查过原因(当时也没修),与 K3 移植无关。

一句话结论:**pipetest 崩溃是 async-os 异步系统调用返回路径的已知遗留 bug(寄存器相关),K3 移植本身没有引入新问题 —— 恰恰相反,能跑到这一步,说明多任务、管道、mmap、调度、异步系统调用入口在 K3 上全都正常工作。**

## 决定与影响

- **决定**:暂时不修(用户提出并确认)。修它不属于 K3 移植的范围。
- **验收门槛调整**:从"pipetest 跑完"改为 —— hello_world 通过 + pipetest 跑到该已知 bug 点为止。这等于"除该遗留 bug 外全部通过"。
- **后续安排**:此 bug 留作 async-debug 上 K3 后的**第一个实战调试目标**——用调试器在真板上抓现场,正好是 async-debug 的本职。届时静态证据链已基本完整,修起来不难。

## 词表

| 词 | 大白话 |
|----|--------|
| ecall | 用户程序"敲门进内核"的指令 |
| trap frame | 内核抄寄存器用的"寄存单"(一张纸,每个寄存器一格) |
| ret_ptr | "收货地址"(结果写回的用户内存地址) |
| EAGAIN | 内核回的"稍等,还没好" |
| ktask | 内核里办这张"外卖单"的服务员 |
| stval | 报警时记录的"踩空地址" |
