# K3 开发记录 08:测例区"撞大页"(MappedToHugePage)的根因与修复

- **日期**:2026-11-10
- **面向读者**:完全没学过硬件也能看懂(概念先行,步骤在后,术语表在最后)

## 这篇记录解决什么问题

修复"幽灵内存区"(记录 07)之后,内核成功走过了内存初始化,却在**加载测例镜像**时撞上了第二个坑,报错 `MappedToHugePage`。这篇记录讲清:这个错是什么意思、为什么 K3 上有而 qemu 上没有、怎么修的。

## 先讲三个概念(每个都用大白话)

### 1. 页表 = 地址的"翻译词典"

CPU 用的地址(虚拟地址,VA)和内存芯片上的真实位置(物理地址,PA)是两套编号。**页表**就是两套编号之间的翻译词典,内核开机时建立。

### 2. 大页(huge page)= 整章翻译,而不是逐字翻译

翻译词典可以有两种粒度:
- **小页(4KB)**:一个字一个字地查,灵活,但词典条目多
- **大页(2MB / 1GB)**:一整章一整章地翻译,省词典空间,但要改其中一页就得**先把整章拆开**

内核开机时为了省事,把整块真实内存**用大页(1GB 一章)一次性翻译好**。

### 3. 重映射 = 想偷偷改词典里的一页

img 模式有个特殊需求:测例镜像嵌在内核文件里(记录 05),启动时要让"测例区地址"临时指向镜像所在的位置,而不是它原本对应的内存。这就要**改词典**:把测例区那一页的翻译目标换掉。

问题来了:测例区在 K3 上位于内存**内部**——那一页已经被"1GB 大页"整章翻译了。想改其中一页,词典程序不会自动拆章,直接报错:**MappedToHugePage**(撞上了大页)。

## 现象(崩溃时发生了什么)

内存清单正常(幽灵内存区已消失),分配器正常,然后:

```
failed to map page: VA:0xffffffc180000000(Size4K) -> PA:0x140150000, MappedToHugePage
panicked at modules/runtime/src/lib.rs:264:23:
called `Result::unwrap()` on an `Err` value: MappedToHugePage
```

- `VA:0xffffffc180000000` = 测例区地址(0x180000000)
- `PA:0x140150000` = 镜像嵌在内核文件里的位置
- 内核想把测例区地址重定向到镜像位置 → 撞上大页 → 崩溃

## 根因(为什么 qemu 没事,K3 有事)

| | qemu 模拟器 | K3 真板(修复前) |
| --- | --- | --- |
| 真实内存范围 | 0x80000000 ~ 0x88000000(128MB) | 0x102000000 ~ 0x300000000(8GB) |
| 测例区放哪 | **0x90000000——在内存外面** | **0x180000000——在内存里面** |
| 重映射测例区时 | 内存外没有大页挡路,随便改 | 内存内已被 1GB 大页占着,撞车 |

qemu 的配置里测例区本来就在内存之外,前人当年写 img 机制时就是这么躲开大页的。K3 移植时,前人把测例区挪进了内存里(注释写"RAM 内安全区域"),当时没有 img 模式所以没暴露问题;我们一开 img 特性,翻译词典一改页,就撞车了。

一句话根因:**K3 把测例区放在了内存内部,而 img 模式需要临时改掉测例区的地址翻译;内存内部已被大页整章翻译,改不了,就报 MappedToHugePage。**

## 修复(改一个配置数字)

文件:`platforms/riscv64-k3.toml`

```toml
# 修复前
testcase-memory-start = "0x1_8000_0000"   # 在内存里,撞大页
# 修复后
testcase-memory-start = "0x3_0000_0000"   # 恰好在内存直映范围末端之后,和 qemu 的做法对齐
```

原理:把测例区挪到内存直映范围**之外**(0x300000000,刚好是内存 8GB 的终点之后)。那里没有大页占路,词典可以随便改;而且挪走之后,内存里 64MB 空间还给堆使用,不再"偷内存"。

安全性检查:全代码库搜过,`testcase-memory-start` 只有两个用途——重映射的目标地址、镜像拷贝的源地址。它**不需要是真实内存**,随便一个空闲地址编号都行。改成 0x300000000 后两处用途照常工作。

## 验证方式

重新构建 → 上板启动。预期:走到"加载测例镜像"不再报错,继续挂载文件系统,跑起 pipetest。

## 术语速查表

| 词 | 一句话解释 |
| --- | --- |
| 页表 | 虚拟地址 ↔ 物理地址的翻译词典 |
| 虚拟地址(VA) | CPU 看到的地址编号(0xffffffc0 开头那一串) |
| 物理地址(PA) | 内存芯片上的真实位置编号 |
| 大页(huge page) | 整章翻译的省事做法;2MB/1GB 粒度 |
| 小页 | 4KB 一页的精细翻译 |
| 重映射 | 临时改写词典里某一页的翻译目标 |
| MappedToHugePage | 报错:"想改的这一页属于一个大页,词典不支持拆章" |
| img 特性 | 把测例镜像烤进内核的机制(记录 05) |
